# Contribuição

1. Crie uma branch curta a partir de `main`.
2. Mantenha mudanças de contrato compatíveis ou publique uma nova versão.
3. Execute `make check` antes do pull request.
4. Não inclua credenciais, IDs reais de tenant/workspace ou dados pessoais.
5. Registre decisões arquiteturais relevantes em `docs/adr`.

Commits devem explicar a intenção da mudança; pull requests devem incluir evidência de teste e impacto em reprocessamento/backfill.
